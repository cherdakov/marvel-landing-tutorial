# Первый лендинг Marvel: учебник для начинающего на Windows

Твоя миссия — сделать страницу с одной кнопкой «Собрать Мстителей», разобраться в её устройстве и опубликовать её в интернете.

Начнём с HTML и CSS: ты будешь менять файлы и сразу видеть результат в браузере. Затем добавим JavaScript, чтобы кнопка реагировала на нажатие. Когда страница заработает, познакомимся с Git, сохраним историю проекта и настроим бесплатный хостинг на GitHub Pages.

В готовом варианте на тёмном фоне находится одна красная кнопка. Нажимаешь — надпись меняется на «Мстители в сборе!». Всё. Даже Тони Старку иногда полезно начать с проекта, который помещается в три файла.

**Подготовка:** компьютер с Windows, доступ в интернет для скачивания программ и немного свободного места. В первых трёх главах достаточно редактора и браузера. Аккаунт GitHub понадобится в четвёртой главе.

**Срок:** ориентировочно 5–7 дней по 60–90 минут, примерно 6–9 часов работы всего. Это оценка с запасом на чтение, установку программ и исправление ошибок. Если работа с папками тоже в новинку, можно двигаться медленнее.

| Занятие | Что проходить | Что получится |
| --- | --- | --- |
| День 1 | Глава 1: файлы, браузер и HTML | Ты видишь свою кнопку на странице |
| День 2 | Глава 2: CSS, цвета и отступы | Страница оформлена в стиле Marvel |
| День 3 | Глава 3: JavaScript и события | Кнопка меняет надпись |
| День 4 | Глава 4: Git и история изменений | Есть первый коммит и понятный способ сохранять версии |
| День 5 | Главы 5–6: GitHub, хостинг и самостоятельные изменения | Сайт открывается по ссылке и обновляется через Git |
| Дни 6–7 | Главы 7–9: ошибки, самопроверка и повторение | Ты можешь объяснить и повторить рабочий процесс |

Во время практики используй цикл **предскажи → измени → проверь → объясни**. Сначала предположи, что произойдёт. Затем поменяй одну вещь, посмотри на результат и объясни его своими словами.

Короткие фрагменты кода внутри объяснений показывают отдельные идеи. Полные версии файлов отмечены явно. Держи на странице одну кнопку: для упражнений достаточно менять её текст, оформление и поведение.

> Лор миссии: Щ.И.Т. потерял доступ к кнопке сбора Мстителей. Бюджет — ноль рублей, разработчик — ты, дедлайн — когда разберёшься. Уровень тревоги: «пупупу». Поехали.

## 1. HTML: сделай страницу и сразу открой её в браузере

### 1.1. Что такое сайт и что мы сейчас строим

Веб-страница — документ, который браузер превращает в видимое содержимое: текст, кнопки, изображения и другие элементы. **Браузер** — программа для открытия страниц, например Edge, Chrome или Firefox.

**Лендинг** — страница, представляющая идею, продукт или событие и ведущая посетителя к основному действию. Наш учебный вариант предельно простой: одна кнопка сбора Мстителей. На ней можно изучить весь путь от разметки до публикации.

Для страницы будем использовать три технологии:

| Технология | За что отвечает | Что делает в нашем проекте |
| --- | --- | --- |
| HTML | Структура и смысл элементов | Создаёт кнопку |
| CSS | Оформление и расположение | Делает кнопку красной и ставит её по центру |
| JavaScript | Действия и реакции на события | Меняет надпись после нажатия |

Сначала создадим только HTML. Кнопка появится в обычном оформлении браузера. Затем ты увидишь, как CSS меняет её внешний вид.

### 1.2. Установи редактор и создай папку

1. Скачай [Visual Studio Code для Windows](https://code.visualstudio.com/download), установи и открой его.
2. В Проводнике Windows открой **Документы** и создай папку `marvel-landing`.
3. В VS Code выбери **File → Open Folder** и открой эту папку.
4. Если редактор спросит, доверяешь ли ты файлам, подтверди доверие для этой папки, которую ты создал сам.
5. В панели файлов редактора нажми **New File** и назови файл `index.html`.

**Редактор** помогает писать текст кода: подсвечивает части документа, показывает номера строк и подсказывает имена. **Браузер** показывает результат исполнения и отображения этого кода. В работе ты будешь переключаться между двумя окнами.

### 1.3. Разберись с именем и расширением файла

У имени `index.html` две части. `index` — имя, а `.html` — расширение, указывающее на HTML-документ. Для нашего будущего хостинга `index.html` будет входной страницей проекта.

В Проводнике включи показ расширений: **Вид → Показать → Расширения имён файлов**. В некоторых версиях Проводника переключатель находится прямо на вкладке **Вид**. Это поможет отличить `index.html` от случайно созданного `index.html.txt`. [Справка Microsoft](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/common-file-name-extensions-in-windows).

Файлы HTML, CSS и JavaScript в этом задании — текстовые. Ты редактируешь их содержимое, сохраняешь на диск, а браузер читает сохранённую версию.

### 1.4. Напиши первый HTML-документ

Вставь в `index.html` полный пример:

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Marvel — Мстители</title>
</head>
<body>
  <!-- Досье №67: Танос спрятал здесь камень. Нашёл? Плюс аура. -->
  <button id="main-button" type="button">Собрать Мстителей</button>
</body>
</html>
```

Нажми **Ctrl+S**. Найди файл в Проводнике и открой в браузере двойным щелчком. Если он открывается в редакторе, выбери **Открыть с помощью → Microsoft Edge** или **Google Chrome**.

Ты должен увидеть кнопку в верхней части страницы. Пока она выглядит обычно и не меняет текст при нажатии: оформление и поведение добавим в следующих главах.

> Первая ачивка: браузер показал твой HTML. Охренеть, у тебя уже есть страница. У Старка был гараж и миллиард долларов, у тебя — папка и одна кнопка. Старт засчитан.

### 1.5. Что такое теги, элементы и атрибуты

Посмотри на эту строку:

```html
<button id="main-button" type="button">Собрать Мстителей</button>
```

- `<button ...>` — открывающий **тег**.
- `</button>` — закрывающий тег. Косая черта показывает конец элемента.
- `Собрать Мстителей` — текстовое содержимое.
- Вся конструкция от открывающего до закрывающего тега — HTML-**элемент**.
- `id="main-button"` и `type="button"` — **атрибуты**, дополнительные настройки элемента.

`id` задаёт уникальный идентификатор. Позже JavaScript найдёт по нему нашу кнопку. `type="button"` явно указывает обычную кнопку; это полезная привычка, особенно когда на странице появятся формы.

HTML описывает назначение элемента. Благодаря настоящему `<button>` браузер уже умеет выбирать его клавишей Tab и нажимать Enter или пробелом. Это одна из причин использовать подходящий элемент, а не пытаться нарисовать кнопку случайным текстом.

### 1.6. Как устроен документ целиком

| Строка или элемент | Для чего нужен |
| --- | --- |
| `<!doctype html>` | Включает современный стандартный режим отображения HTML |
| `<html lang="ru">` | Объединяет документ и указывает русский язык |
| `<head>` | Содержит настройки и подключения файлов |
| `<meta charset="UTF-8">` | Задаёт кодировку, чтобы текст, включая кириллицу, читался правильно |
| `<meta name="viewport" ...>` | Настраивает отображение по ширине экрана мобильного устройства |
| `<title>` | Задаёт название вкладки браузера |
| `<body>` | Содержит элементы, отображаемые на странице |

Элементы вложены друг в друга: `head` и `body` находятся внутри `html`, а кнопка — внутри `body`. Отступы в коде помогают видеть эту структуру. Для браузера в этом примере ширина отступа не меняет расположение кнопки.

У некоторых элементов, например `meta` и `link`, закрывающего тега нет: их называют пустыми элементами. Не нужно добавлять `</meta>`.

Текст между `<!--` и `-->` — **комментарий**. Браузер не показывает его на странице. Так можно оставить пояснение или небольшую пасхалку для человека, читающего код. Комментарий доступен тому, кто откроет исходник: хранить в нём настоящие секреты нельзя.

### 1.7. Измени страницу и проверь результат

1. Замени текст кнопки на «Позвать героев».
2. Сохрани файл через Ctrl+S.
3. Переключись в браузер и нажми **Ctrl+R**.
4. Убедись, что надпись изменилась.
5. Верни «Собрать Мстителей», сохрани и обнови страницу ещё раз.

Изменения файла и обновление страницы — два отдельных действия. В этой схеме браузер сам не перечитывает файл после каждого сохранения.

> «Блядь, я же всё поменял, почему на экране старое?» Классика. Проверь Ctrl+S в редакторе, потом Ctrl+R в браузере. Иногда весь финальный босс — несохранённый файл.

Теперь измени содержимое `<title>`, например на `Marvel — мой первый сайт`. Посмотри, где появился новый текст. Так ты увидишь разницу между настройками документа и его видимым содержимым. После эксперимента верни исходное название.

Если забыть закрывающий тег, браузер иногда пытается сам исправить разметку. Поэтому страница может выглядеть приемлемо даже с ошибкой. Проверяй структуру в редакторе, а не только внешний вид.

### Проверь понимание

1. Чем редактор отличается от браузера?
2. Что такое элемент и чем он отличается от тега?
3. Где меняется текст кнопки, а где — название вкладки?
4. Почему после изменения файла нужно сохранить его и обновить страницу?

**Результат главы:** файл `index.html` открыт в браузере, на странице одна кнопка, и ты можешь самостоятельно изменить её надпись.

Дополнительное чтение: [создание содержимого страницы, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website/Creating_the_content).

## 2. CSS: преврати обычную кнопку в кнопку Мстителей

### 2.1. Что такое CSS

CSS — язык правил оформления. Ты выбираешь элемент и задаёшь, как он должен выглядеть: цвет, размер текста, отступы, положение.

HTML-кнопка уже существует. Теперь изменим её вид, сохранив назначение и текст.

### 2.2. Подключи файл оформления

1. Создай в той же папке файл `style.css`.
2. В `index.html` добавь после строки с `<title>` эту строку:

```html
  <link rel="stylesheet" href="./style.css">
```

`link` подключает внешний ресурс. `rel="stylesheet"` говорит, что это таблица стилей, а `href` указывает путь к файлу.

`./style.css` означает «файл `style.css` в той же папке, где находится эта страница». Это **относительный путь**. Он пригодится и при публикации: вместо пути на конкретном диске мы используем расположение файлов внутри проекта.

Проверь имена: `style.css` и `styles.css` — разные файлы. Сохраняй их в одной папке с `index.html`.

### 2.3. Сначала проверь, что CSS подключился

Вставь в `style.css`:

```css
body {
  background: #101014;
}
```

Сохрани оба файла и обнови страницу. Фон должен стать тёмным. Это первая проверка связи между HTML и CSS.

Если фон не изменился, проверь имя файла, строку `link` и сохранение. Пока этот маленький пример не заработал, удобнее разобраться с ним, чем добавлять сразу много правил.

### 2.4. Добавь полное оформление

Теперь замени содержимое `style.css` на полный вариант:

```css
body {
  /* Танос убрал половину отступов. Мы убрали остальные. */
  margin: 0;
  min-height: 100vh;
  display: grid;
  place-items: center;
  background: #101014;
  font-family: Arial, sans-serif;
}

button {
  padding: 16px 28px;
  border: 0;
  border-radius: 12px;
  background: #c8102e;
  color: white;
  font-size: 20px;
  cursor: pointer;
}

button:hover {
  background: #a30d26;
}

button:focus-visible {
  outline: 3px solid #fbbf24;
  outline-offset: 4px;
}
```

Сохрани файл и обнови страницу. Кнопка должна стать красной и переместиться в центр тёмного экрана.

### 2.5. Как читать CSS-правило

Пример отдельного правила:

```css
button {
  color: white;
}
```

`button` — **селектор**: он выбирает элементы, к которым относится правило. В фигурных скобках находятся объявления свойств. `color` — свойство, `white` — значение. Двоеточие отделяет свойство от значения, точка с запятой завершает объявление.

В нашем примере селекторы `body` и `button` выбирают элементы по имени тега. Селектор `#main-button` выбрал бы элемент по `id`. Здесь `#` — часть синтаксиса селектора; в HTML сам идентификатор записывается без `#`.

Браузер может применить к одному элементу несколько правил. Поэтому проверь весь файл, если новое значение неожиданно перекрывается другим. При двух обычных правилах с одинаковым селектором и одинаковым приоритетом одноимённое свойство из более позднего правила перекроет раннее.

### 2.6. Цвета, размеры и отступы

| Свойство | Что означает на нашей странице |
| --- | --- |
| `background: #101014` у `body` | Тёмный фон страницы |
| `background: #c8102e` у `button` | Красный фон кнопки |
| `color: white` | Белый цвет текста кнопки |
| `font-size: 20px` | Размер текста в CSS-пикселях |
| `padding: 16px 28px` | Внутренний отступ: 16 пикселей сверху и снизу, 28 слева и справа |
| `border: 0` | Убирает обычную границу кнопки |
| `border-radius: 12px` | Скругляет углы |
| `cursor: pointer` | Показывает указатель-«руку» при наведении мыши |

Цвет можно записать словом, например `white`, или шестнадцатеричным кодом вроде `#c8102e`. Начальный `#` в коде цвета относится к формату цвета; в селекторе `#main-button` он выполняет другую роль. Смысл зависит от места записи.

**CSS-пиксель**, сокращённо `px`, — единица размера в CSS. `vh` зависит от высоты окна: `100vh` соответствует полной высоте области просмотра, используемой этой единицей. На телефонах панели браузера могут влиять на видимую область; для первого примера начнём с этой простой записи.

### 2.7. Что такое блочная модель

Для расчёта размеров браузер рассматривает элемент как прямоугольную область с несколькими слоями:

```text
содержимое → внутренний отступ padding → граница border → внешний отступ margin
```

У нашей кнопки содержимое — надпись. `padding` создаёт место вокруг надписи внутри кнопки. `border` проходит по её краю. `margin` задаёт внешние отступы относительно окружающих элементов.

Поэтому увеличение `padding` делает цветную область кнопки крупнее, а увеличение `font-size` меняет размер самой надписи. Эти действия дают разный результат. [Блочная модель, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Box_model).

### 2.8. Почему кнопка оказалась по центру

Эти свойства работают вместе:

- `margin: 0` убирает стандартные внешние отступы `body`.
- `min-height: 100vh` задаёт странице минимальную высоту окна.
- `display: grid` включает Grid для размещения дочерних элементов.
- `place-items: center` выравнивает кнопку по центру её области внутри Grid.

Поскольку внутри `body` один видимый элемент, получается одна кнопка по центру страницы.

> Кнопка по центру. Заебись. CSS-вайбчек пройден, а Тор наконец вышел из угла семейного созвона с Локи.

### 2.9. Наведение и управление с клавиатуры

`button:hover` срабатывает при наведении мыши. Это **псевдокласс** — способ выбрать элемент в определённом состоянии. Фон становится чуть темнее, и пользователь видит реакцию.

`button:focus-visible` задаёт заметную рамку при видимом фокусе, например при выборе кнопки клавишей Tab. Благодаря рамке человек понимает, какой элемент сейчас выбран. `outline` рисует такую рамку, а `outline-offset` отодвигает её от края.

Проверь: нажми Tab, найди рамку, затем нажми Enter. Сейчас надпись ещё не меняется, но выбор и нажатие доступны. Сохрани эту возможность, когда будешь менять дизайн.

### Мини-эксперименты

Каждый раз сохраняй файл, обновляй браузер и меняй только одно значение. После наблюдения можно вернуть исходное оформление.

1. Измени `border-radius: 12px` на `0`. Что случилось с углами?
2. Измени `padding: 16px 28px` на `24px 40px`. Что увеличилось?
3. Увеличь `font-size` до `24px`. Чем эффект отличается от изменения `padding`?
4. Придумай цвет кнопки в стиле любимого героя Marvel. Подбери и цвет наведения.

После опытов верни полную версию CSS из пункта 2.4. Так в следующих главах у тебя будет тот же исходный вариант, что и в примерах. Свою палитру сохранишь отдельным изменением в самостоятельной практике.

**Проверка:** на странице одна кнопка, текст читается, кнопка расположена по центру, наведение и рамка фокуса заметны. Сузь окно браузера примерно до ширины телефона: кнопка должна помещаться.

**Объясни:** чем `color` отличается от `background`, а `padding` — от `margin`? Как HTML узнаёт о существовании `style.css`?

Дополнительное чтение: [начало работы с CSS, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Getting_started).

## 3. JavaScript: научи кнопку реагировать на нажатие

### 3.1. Зачем нужен JavaScript

HTML описал кнопку, а CSS оформил её. Теперь нам нужно действие: после нажатия поменять надпись. Для этого напишем небольшую программу на JavaScript.

В этом проекте JavaScript выполняется браузером. Устанавливать отдельный сервер для нашей кнопки не требуется.

### 3.2. Подключи скрипт

1. Создай рядом с `index.html` файл `script.js`.
2. После строки подключения CSS, внутри `head`, добавь:

```html
  <script src="./script.js" defer></script>
```

`src` указывает путь к скрипту. `defer` откладывает его выполнение до разбора HTML-документа: кнопка уже будет создана, когда программа начнёт её искать.

Итоговая полная версия `index.html`:

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Marvel — Мстители</title>
  <link rel="stylesheet" href="./style.css">
  <script src="./script.js" defer></script>
</head>
<body>
  <!-- Досье №67: Танос спрятал здесь камень. Нашёл? Плюс аура. -->
  <button id="main-button" type="button">Собрать Мстителей</button>
</body>
</html>
```

### 3.3. Напиши программу

Полное содержимое `script.js`:

```javascript
// Служебный канал Щ.И.Т. Сообщение появится в консоли браузера.
console.log("[Щ.И.Т.] Допуск 67. Пасхалка найдена: +100 к ауре.");

const button = document.querySelector("#main-button");

function handleClick() {
  button.textContent = "Мстители в сборе!";
}

button.addEventListener("click", handleClick);
```

Выбери **File → Save All**, обнови страницу и нажми кнопку.

**Результат:** надпись меняется на «Мстители в сборе!». Повторное нажатие оставляет ту же надпись: программа каждый раз присваивает один и тот же текст.

### 3.4. Как JavaScript находит элемент: DOM

Разбирая HTML, браузер строит в памяти представление документа — **DOM**, от *Document Object Model*. Его удобно представить как дерево элементов: внутри `html` есть `head` и `body`, а внутри `body` — кнопка.

Через DOM JavaScript получает доступ к элементам и меняет их свойства. `document` в программе представляет текущий документ. Вызов `document.querySelector("#main-button")` ищет первый элемент с этим селектором и возвращает ссылку на него.

Когда мы меняем `textContent`, браузер обновляет текст соответствующего элемента. Исходный файл `index.html` на диске при этом остаётся тем, который ты сохранил в редакторе. [Работа с DOM, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/DOM_scripting).

### 3.5. Переменная, значение и строка

Разберём первую рабочую строку:

```javascript
const button = document.querySelector("#main-button");
```

**Переменная** позволяет обратиться к значению по имени. Здесь имя `button` связано со ссылкой на найденный элемент.

`const` означает, что этому имени нельзя присвоить другое значение. При этом свойства самого элемента менять можно: именно поэтому следующая программа сможет обновить `button.textContent`. Подробнее: [объявление const, MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/const).

Текст в кавычках, например `"Мстители в сборе!"`, называется **строкой**. Значок `=` в присваивании означает «поместить значение справа в указанное место слева». В выражении `button.textContent = ...` это место — свойство текста у элемента кнопки.

Если селектор содержит опечатку и элемент не найден, `querySelector` вернёт `null`, то есть отсутствие найденного объекта. Попытка работать с ним как с кнопкой приведёт к ошибке. В седьмой главе научишься искать её в консоли.

### 3.6. Функция и событие

**Функция** — именованный фрагмент программы, который можно вызвать, чтобы выполнить действие:

```javascript
function handleClick() {
  button.textContent = "Мстители в сборе!";
}
```

Объявление функции описывает, что делать. Строка внутри фигурных скобок выполняется при её вызове.

**Событие** — сообщение о том, что что-то произошло: нажатие, ввод текста, движение мыши. В нашем случае нас интересует `click`.

```javascript
button.addEventListener("click", handleClick);
```

Эта строка регистрирует **обработчик события**: браузер запоминает, что при нажатии нужно вызвать `handleClick`.

Обрати внимание на отсутствие скобок после `handleClick` в этой строке. Мы передаём функцию для последующего вызова. Запись `handleClick()` вызвала бы её сразу во время выполнения этой строки.

### 3.7. Что происходит по порядку

```text
Браузер разбирает HTML → выполняет отложенный скрипт → находит кнопку
→ регистрирует обработчик → ждёт нажатия → вызывает функцию → меняет надпись
```

Ожиданием нажатия занимается браузер. Нам достаточно описать нужную реакцию.

После обновления страницы браузер заново читает HTML и создаёт документ с начальной надписью «Собрать Мстителей». Наша программа не сохраняет изменённый текст между загрузками — поэтому надпись возвращается.

### 3.8. Консоль и секретный канал Щ.И.Т.

В Chrome или Edge нажми **Ctrl+Shift+J** и открой вкладку **Console**, если она не выбрана автоматически. Обнови страницу.

Ты увидишь сообщение из `console.log`. Эта команда выводит информацию для разработчика в консоль, а не добавляет текст на страницу. Позже так можно проверять, до какого места дошла программа и какие значения она получила.

`//` начинает однострочный комментарий в JavaScript. В CSS комментарии окружают символами `/* ... */`, а в HTML — `<!-- ... -->`. Языки разные, поэтому и обозначения отличаются.

## 4. Git: научись сохранять версии проекта

### 4.1. Зачем вообще нужен Git

У тебя уже есть работающая страница. Представь, что ты полчаса менял цвет, надпись и код кнопки. В какой-то момент она перестала реагировать. Хочется узнать, что изменилось, и вернуться к рабочему варианту.

Можно перед каждым экспериментом копировать папку: `сайт-1`, `сайт-2`, `сайт-финальный`, `сайт-финальный-точно`. Но в такой коллекции быстро становится трудно ориентироваться.

**Git — система контроля версий.** Она позволяет сохранять состояния проекта, сравнивать изменения и возвращаться к сохранённым вариантам. Это полезно и одному человеку, и команде. Общая история помогает понять, кто, когда и зачем поменял файл. [Зачем нужен контроль версий, руководство Git](https://git-scm.com/book/en/v2/Getting-Started-About-Version-Control).

В нашем проекте Git поможет:

- сохранить работающую кнопку перед экспериментом;
- увидеть конкретные изменённые строки;
- восстановить сохранённую версию файла;
- объяснить, что сделано на каждом занятии;
- отправить историю на GitHub и использовать её для публикации.

Git записывает версии, которые ты сам добавляешь в историю. Нажатие Ctrl+S сохраняет файл на диск; для создания версии в Git потребуется отдельное действие.

> Папка `финал_последний_точно_это_он_7` — мощный артефакт. Побочный эффект: через неделю нихуя не понятно, где рабочий сайт. Git помогает сохранить версии и подписать, что именно в них менялось.

### 4.2. Репозиторий, коммит и ветка

**Репозиторий** — проект вместе с историей Git и служебными данными. У обычного локального репозитория эта история хранится в скрытой папке `.git` внутри проекта.

**Коммит** — сохранённое состояние отслеживаемых файлов с описанием, автором и связью с предыдущей историей. У него есть идентификатор — длинная последовательность символов. В кратком выводе Git показывает её начало.

Удобно представлять коммиты как точки на линии работы:

```text
Работающая кнопка → Новый цвет → Исправленный текст
    коммит A         коммит B         коммит C
```

Каждая точка позволяет посмотреть состояние проекта на этом этапе. Git также умеет показывать различия между точками.

**Ветка** — именованная линия работы, технически ссылка на коммит, которая перемещается при новых коммитах в этой ветке. Основную ветку нашего проекта назовём `main`. На этом этапе будем работать в ней. Отдельные ветки для экспериментов можно изучить позже.

Первый коммит появится только сейчас. Git не восстановит промежуточные версии из первых трёх глав, которые ты не сохранял в историю.

### 4.3. Установи Git и открой терминал

1. Скачай [Git для Windows с официальной страницы](https://git-scm.com/install/windows).
2. Выбери установщик для своего компьютера; для большинства обычных ПК подходит **x64 Setup**.
3. Оставь включённым **Git Credential Manager**, если установщик предлагает этот компонент. Он пригодится для входа в GitHub.
4. В настройке доступности Git выбери **Git from the command line and also from 3rd-party software**, если видишь такой выбор.
5. Заверши установку и полностью перезапусти VS Code.
6. Открой папку `marvel-landing` через **File → Open Folder**.
7. Выбери **Terminal → New Terminal**. Для следующих команд используй **PowerShell**. Оболочку можно выбрать через стрелку рядом с кнопкой создания терминала.
8. Введи:

```powershell
git --version
```

**Проверка:** появилась строка с версией Git. Если команда не найдена, перезапусти редактор и проверь установку.

### 4.4. Что такое терминал и как читать команды

**Терминал** — окно, через которое ты работаешь с текстовыми командами. **PowerShell** — командная оболочка, которая разбирает строки и запускает нужные действия.

Команда `git --version` состоит из имени программы `git` и параметра `--version`, который просит вывести её версию. В `git status` слово `status` — команда самой программы Git.

Команды работают относительно **текущей папки**. Её обычно видно в приглашении терминала, например `PS C:\Users\Alex\Documents\marvel-landing>`. Это приглашение переписывать не нужно.

Вводи команды по одной строке, нажимай Enter и читай результат. Попробуй:

```powershell
Get-Location
Get-ChildItem
```

Первая покажет текущую папку, вторая — её содержимое. Перед следующим шагом убедись, что видишь папку `marvel-landing` и файлы `index.html`, `style.css`, `script.js`. Если открылось другое место, снова выбери папку проекта через **Open Folder** и создай новый терминал.

Полный путь, например `C:\Users\Alex\Documents\marvel-landing`, называется **абсолютным**. Имя `style.css` внутри текущей папки — относительный путь. Эта идея похожа на пути подключения файлов в HTML.

### 4.5. Создай локальный репозиторий

В терминале папки проекта выполни:

```powershell
git init -b main
git status
```

`git init` создаёт служебные данные репозитория, а `-b main` задаёт имя первой ветки. Файлы страницы останутся на месте. [Описание git init](https://git-scm.com/docs/git-init).

`git status` покажет, что коммитов ещё нет, а файлы имеют состояние `untracked`: Git видит их в папке, но ещё не начал учитывать их в истории.

Создание репозитория сейчас происходит на твоём компьютере. Публикацию в интернете настроим в следующей главе.

### 4.6. Настрой автора коммитов

Коммиты содержат имя и email автора. Перед первой записью укажем никнейм и специальный адрес GitHub `noreply`, чтобы использовать его в публичной истории.

1. Открой [GitHub](https://github.com/), зарегистрируй свой аккаунт, если его ещё нет, и подтверди почту.
2. Нажми на аватар → **Settings → Emails**.
3. Включи **Keep my email addresses private**.
4. Скопируй показанный GitHub адрес с окончанием `@users.noreply.github.com`.
5. В терминале папки проекта введи команды, заменив значения в кавычках своими:

```powershell
git config --local user.name "YOUR_NICKNAME"
git config --local user.email "YOUR_GITHUB_NOREPLY_EMAIL"
```

`--local` применяет настройку к этому репозиторию. Вместо `YOUR_NICKNAME` впиши свой ник, вместо `YOUR_GITHUB_NOREPLY_EMAIL` — скопированный адрес целиком. Настройка имени и почты подписывает коммиты; вход в аккаунт для отправки изменений будет отдельным шагом. [Почта автора коммитов, GitHub Docs](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

Проверь значения:

```powershell
git config --local user.name
git config --local user.email
```

### 4.7. Добавь описание проекта

Создай файл `README.md` в папке проекта. Он нужен человеку, который впервые открыл репозиторий: объясняет, что здесь находится и как это запустить.

`.md` — расширение **Markdown**, текстового формата для заметок и документации. Например, `#` в начале строки обозначает заголовок, а `-` — пункт списка.

Содержимое README:

```markdown
# Marvel Landing

Учебный фан-лендинг Marvel с одной кнопкой сбора Мстителей.

## Как открыть

Открой index.html в браузере.

## Файлы

- index.html — структура страницы.
- style.css — оформление.
- script.js — поведение кнопки.
```

Сохрани все файлы. Теперь в папке четыре основных файла и скрытая папка `.git`.

### 4.8. Три места, которые важно различать

До первого коммита разберись с рабочей папкой, подготовленными изменениями и историей:

| Место | Что там находится | Действие |
| --- | --- | --- |
| Рабочая папка | Файлы, которые ты редактируешь | Меняешь код и сохраняешь через Ctrl+S |
| Область подготовки, или staging area | Версии файлов, выбранные для следующего коммита | Добавляешь через `git add` |
| История репозитория | Уже созданные коммиты | Записываешь через `git commit` |

Область подготовки позволяет выбрать, какие изменения войдут в следующую запись. Например, можно сохранить отдельным коммитом оформление, а затем отдельно описание README.

`git add` подготавливает текущую версию файла. Если после этого снова изменить и сохранить файл, для новой версии нужно повторить `git add`. [Рабочая папка и область подготовки, руководство Git](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F).

### 4.9. Сделай первый коммит

Посмотри состояние файлов и подготовь их:

```powershell
git status
git add index.html style.css script.js README.md
git diff --staged
```

`git diff --staged` покажет, что войдёт в коммит. При первом сохранении это всё содержимое новых файлов. Если открылся просмотр на весь терминал, нажми `q`, чтобы выйти.

Теперь создай коммит:

```powershell
git commit -m "Create Marvel button page"
git status
```

`-m` задаёт сообщение — короткое объяснение смысла изменений. Можно писать по-русски, например `Создал страницу с кнопкой Мстителей`.

**Проверка:** после коммита `git status` показывает `nothing to commit, working tree clean`. Это значит, что текущие отслеживаемые файлы соответствуют сохранённому состоянию, а ожидающих изменений нет.

Сообщение коммита должно помогать будущему тебе. `Изменил цвета кнопки` полезнее, чем `Ну вроде теперь норм`, хотя второй вариант иногда отражает весь спектр эмоций разработчика.

> Коммит с сообщением «починил какую-то хрень» искренний, но через неделю придётся выяснять, какую именно. Напиши «Исправил подключение CSS» — будущий ты скажет спасибо.

> Ачивка: первый коммит. Рабочая кнопка получила точку сохранения. Тони Старк одобряет, Локи уже ищет способ назвать коммит `абоба`.

### 4.10. Посмотри историю и различия

```powershell
git log --oneline
```

Ты увидишь краткую строку: идентификатор коммита и сообщение. Пока коммит один. После следующих изменений новые записи появятся выше старых.

Теперь измени в `style.css` радиус углов с `12px` на `24px`, сохрани файл и выполни:

```powershell
git diff -- style.css
```

Внутри вывода появится примерно такой фрагмент:

```diff
-  border-radius: 12px;
+  border-radius: 24px;
```

Строка с `-` — старый вариант, с `+` — новый. Это и есть **diff**, сравнение изменений. Символы `-` и `+` здесь показываются Git; добавлять их в CSS не нужно.

Проверь кнопку в браузере. Если всё работает, сохрани изменение отдельным коммитом:

```powershell
git add style.css
git diff --staged
git commit -m "Round the Marvel button corners"
git log --oneline
```

Теперь у тебя две точки в истории. Ты можешь объяснить, какое изменение соответствует каждой.

### 4.11. Эксперимент: восстанови файл после пробного изменения

Попробуем одну из полезных возможностей Git на маленьком контролируемом примере.

1. Выполни `git status`. Начинай, когда видишь `working tree clean`: нужные изменения уже закоммичены.
2. В `style.css` временно поменяй фон кнопки на `lime`.
3. Сохрани файл и обнови браузер.
4. Посмотри изменение через `git diff -- style.css`.
5. В этом эксперименте оставь изменение вне области подготовки: команду `git add` для него выполнять не нужно.
6. Верни сохранённую версию командой:

```powershell
git restore -- style.css
```

Команда заменяет рабочую версию указанного файла содержимым из области подготовки. В нашем эксперименте она совпадает с последним коммитом, потому что после него мы ничего не добавляли через `git add`. Пробная замена на `lime` будет отброшена. Используй эту команду здесь именно для пробного изменения, которое решил убрать. [Описание git restore](https://git-scm.com/docs/git-restore).

Обнови страницу и выполни `git status`. Цвет должен вернуться к сохранённому, а рабочая папка снова стать чистой.

> Лаймовая кнопка оказалась слишком мощной даже для Халка. «Уберите нахрен этот кислотный огурец». Git вернул сохранённый цвет. Аура восстановлена, огурец обезврежен.

## 5. GitHub и хостинг: опубликуй готовую страницу

### 5.1. Раздели роли Git, GitHub и GitHub Pages

| Инструмент | Его роль |
| --- | --- |
| Git | Программа для управления версиями на твоём компьютере |
| GitHub | Сервис для хранения удалённого репозитория и совместной работы |
| GitHub Pages | Сервис публикации сайта из файлов репозитория |

Ты уже сделал коммиты локально. Они работают без интернет-соединения. Теперь отправишь их на GitHub, чтобы удалённый репозиторий получил твою историю.

Коммит сохраняет историю на компьютере, `push` отправляет её на GitHub, а деплой размещает новую версию на хостинге. Это отдельные шаги, и у каждого есть свой результат.

### 5.2. Что такое хостинг и как посетитель получает страницу

Пока ты открывал адрес, начинающийся с `file:///`: браузер читал файлы твоего компьютера. Для другого человека путь `C:\...` с твоего диска бесполезен — ему нужен сетевой адрес сайта.

**Хостинг** размещает файлы на сервере, который отвечает на запросы посетителей. **Клиентом** в нашем примере будет браузер посетителя. Упрощённая последовательность такая:

```text
Посетитель открывает адрес → браузер запрашивает HTML у сервера
→ получает HTML и подключённые файлы → показывает оформленную страницу
```

JavaScript выполняется в браузере. Наша кнопка меняет текст без дополнительного запроса к серверу, а у каждого посетителя свой открытый документ. Подробнее: [как работает веб, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Web_standards/How_the_web_works).

GitHub Pages подходит для **статического сайта**: публикует подготовленные HTML, CSS, JavaScript и другие файлы. Такая страница может быть интерактивной за счёт JavaScript. Собственной серверной программы в нашем проекте нет. [Что такое GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

### 5.3. Создай пустой репозиторий на GitHub

Открой GitHub под аккаунтом, который использовал при настройке автора коммитов.

1. Нажми **+ → New repository**.
2. В поле **Repository name** введи `marvel-landing`.
3. Выбери **Public**: в этом маршруте используем бесплатную публикацию публичного репозитория.
4. Оставь выключенным **Add README**. README и история уже созданы на твоём компьютере.
5. Оставь без добавления `.gitignore` и лицензии на этом шаге.
6. Нажми **Create repository**.

Репозиторий должен быть пустым. Мы отправим в него существующую локальную историю. [Создание репозитория, GitHub Docs](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository).

Файлы и историю публичного репозитория смогут читать другие люди. Для учебного проекта достаточно кода и описания из задания; реальные пароли, ключи доступа и личные данные в них добавлять не нужно.

### 5.4. Свяжи локальный репозиторий с GitHub

На странице пустого репозитория выбери адрес **HTTPS**. Он выглядит так:

```text
https://github.com/YOUR_USERNAME/marvel-landing.git
```

`YOUR_USERNAME` — твой логин, а не буквальный текст команды. Замени его своим логином или скопируй адрес с GitHub.

В терминале папки проекта выполни:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/marvel-landing.git
git remote -v
```

**Remote** — настройка связи с другим репозиторием. `origin` — имя, под которым мы сохранили эту связь. Команда `git remote -v` покажет адреса для получения и отправки изменений.

Теперь отправь коммиты:

```powershell
git push -u origin main
```

`push` передаёт коммиты. `origin` указывает, куда отправлять, `main` — какую ветку. Параметр `-u` запоминает связь локальной ветки с удалённой; после этого обычно достаточно команды `git push`.

При первом обращении Git Credential Manager может открыть окно входа в GitHub. Войди в тот же аккаунт в браузере и заверши предложенную авторизацию. При этом способе вручную создавать токен не требуется. [Авторизация Git, GitHub Docs](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git).

**Проверка:** обнови страницу репозитория. На вкладке **Code** появились четыре файла, а в истории видны твои коммиты.

### 5.5. Включи GitHub Pages

1. Открой **Settings** внутри репозитория.
2. В левом меню выбери **Pages**.
3. В блоке **Build and deployment** установи:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main`;
   - **Folder:** `/ (root)`.
4. Нажми **Save**.
5. Открой вкладку **Actions** и дождись успешного завершения публикации Pages.
6. Вернись в **Settings → Pages** и открой ссылку рядом с сообщением **Your site is live at** или кнопкой **Visit site**.

`/ (root)` — корень проекта, верхний уровень папки, в котором лежит `index.html`. Публикация может занять несколько минут; иногда изменения появляются в течение 10 минут. [Настройка источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Адрес сайта:

```text
https://YOUR_USERNAME.github.io/marvel-landing/
```

GitHub Pages доступен бесплатно для публичных репозиториев на GitHub Free. `YOUR_USERNAME.github.io` — бесплатный поддомен сервиса, а `/marvel-landing/` — путь к проекту. Покупать отдельный домен для этого задания не требуется. Поле **Custom domain** оставь пустым. [Условия GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

**Доменное имя** — читаемое имя сайта. **URL** — полный адрес. В нашем URL `https://` указывает способ обращения с защищённым соединением, `YOUR_USERNAME.github.io` — имя хоста, `/marvel-landing/` — путь.

### 5.6. Ссылка на проект и ссылка на сайт

| Ссылка | Для чего нужна |
| --- | --- |
| `https://github.com/YOUR_USERNAME/marvel-landing` | Файлы, история и настройки репозитория |
| `https://YOUR_USERNAME.github.io/marvel-landing/` | Готовая страница с кнопкой |

Отправь ссылку на готовую страницу себе на телефон и открой её. Посетители получают файлы от GitHub Pages, поэтому твой компьютер может быть выключен.

Проверь надпись, оформление и реакцию кнопки. Так ты убедишься, что опубликована нужная версия, а не только открыта локальная копия.

> Деплой завершён. Бюджет — ноль, кнопка — в интернете. Охренеть, у Мстителей появился фронтендер. Можно открыть ссылку на телефоне и торжественно нажать единственную кнопку: демонстрация продукта должна быть убедительной.

### 5.7. Зачем нужны push, pull и clone

Это три разных действия:

| Команда | Что делает |
| --- | --- |
| `git push` | Отправляет локальные коммиты в удалённый репозиторий |
| `git pull` | Получает изменения и пытается включить их в текущую ветку |
| `git clone` | Создаёт локальную копию репозитория с историей и настройкой связи |

Клонирование понадобится, например, если ты захочешь работать на другом компьютере. В этом учебнике мы начали с локальных файлов и команды `git init`, поэтому клонировать проект поверх текущей папки не нужно.

Для нового компьютера или отдельной папки команда выглядела бы так:

```powershell
git clone https://github.com/YOUR_USERNAME/marvel-landing.git
```

Получение изменений важно, когда проект редактируется в нескольких местах. Перед новым занятием с чистой рабочей папкой можно выполнить `git pull --ff-only`. Этот вариант обновит ветку, если её можно просто продвинуть вперёд; при расходящейся истории он остановится и попросит разобраться. Получив такую ошибку впервые, сохрани её текст и обратись за помощью. [Работа с удалёнными репозиториями](https://git-scm.com/book/en/v2/Git-Basics-Working-with-Remotes).

## 6. Самостоятельная практика: проведи изменения от редактора до сайта

Теперь ты прошёл весь маршрут. Осталось повторить его самостоятельно и убедиться, что понимаешь отдельные этапы.

### 6.1. Рабочая последовательность

```text
Изменить файл → сохранить → проверить локально → посмотреть diff
→ подготовить через add → создать commit → отправить push → проверить деплой
```

Меняй одну вещь за раз. Так проще заметить связь между строкой кода и результатом, а при ошибке будет меньше вариантов, где искать причину.

После каждого упражнения делай отдельный коммит. Например, для изменения CSS:

```powershell
git status
git diff
git add style.css
git diff --staged
git commit -m "Change Marvel button appearance"
git push origin main
```

После `push` дождись публикации во вкладке **Actions**, затем открой сайт по адресу с `github.io` и проверь результат. Локальная вкладка с `file:///` не доказывает, что сайт обновился в интернете.

### 6.2. Упражнение A: измени HTML

Поменяй начальную надпись кнопки на свой короткий текст, например «Позвать героев».

**Предскажи:** какая надпись будет до нажатия, после нажатия и после обновления страницы?

**Проверь:** исходный текст берётся из HTML, а после нажатия отображается сообщение из JavaScript. Сохрани изменение коммитом и опубликуй.

### 6.3. Упражнение B: измени CSS

Придумай палитру в стиле любимого героя Marvel. Измени основной цвет кнопки, цвет наведения и степень скругления углов.

**Предскажи:** какое из правил управляет цветом до наведения, а какое — во время наведения?

**Проверь:** текст читается, кнопка помещается в узком окне, фокус с клавиатуры заметен. Сохрани изменение отдельным коммитом и опубликуй.

> Вайб может быть супергеройским, но белый текст на почти белой кнопке — уже суперспособность по поиску невидимого. Проверь контраст глазами и выбери различимые цвета.

### 6.4. Упражнение C: измени JavaScript

Поменяй сообщение после нажатия, например на «Команда готова к миссии!».

**Предскажи:** изменится ли начальная надпись в HTML после редактирования только `script.js`?

**Проверь:** до нажатия отображается текст из HTML, после — новый текст из JavaScript. После обновления возвращается начальная надпись. Сохрани изменение отдельным коммитом и опубликуй.

### 6.5. Задание со звёздочкой: оформи README

Добавь в `README.md` ссылку на опубликованную страницу и два предложения: что ты уже умеешь и какое затруднение смог решить.

Подготовь этот файл через `git add README.md`, сделай отдельный коммит и отправь его на GitHub. Открой репозиторий и убедись, что описание обновилось.

Пример честной записи: «Сначала CSS не подключался: я назвал файл styles.css, а в HTML написал style.css. Сверил имена, исправил — заработало». Такая запись полезнее, чем «всё само получилось, я сигма».

## 7. Отладка: что делать, когда «блин, ничего не работает»

### 7.1. Ошибка — это задача с наблюдаемыми признаками

Отладка — поиск причины неправильного поведения и проверка исправления. Она входит в обычную разработку. Даже маленькая опечатка может нарушить работу, поэтому полезнее собирать факты, чем одновременно переписывать всё подряд.

Начни с трёх вопросов:

1. **Чего я ожидал?** Например, красной кнопки по центру.
2. **Что получилось?** Например, обычная серая кнопка в углу.
3. **Что менялось последним?** Например, имя CSS-файла.

В таком примере стоит проверить подключение CSS. Сам текст кнопки виден, значит браузер прочитал HTML; оформление отсутствует, значит нужно начать с пути к стилям и содержимого CSS.

> «Какого хуя кнопка не работает?» — эмоциональная часть расследования. Следом открываем Console: у неё обычно есть показания. Сначала читаем ошибку, потом решаем, на какую строчку ругаться.

### 7.2. Проверь простые вещи

1. Сохранены ли файлы? Используй **File → Save All**.
2. Обновлена ли страница?
3. Та ли вкладка открыта: локальная или опубликованная?
4. Правильно ли написаны имена файлов и `id` кнопки?
5. Если это сайт в интернете, завершились ли `push` и публикация?

Потом сделай одно предполагаемое исправление и повтори проверку. Несколько одновременных изменений мешают понять, какое из них помогло.

### 7.3. Как читать ошибку JavaScript

Открой **Ctrl+Shift+J → Console**, обнови страницу и нажми кнопку. Найди первое красное сообщение, связанное со своим скриптом. Обычно рядом указаны имя файла и номер строки.

Например, если написать `#main-buton` вместо `#main-button`, элемент не найдётся. При вызове `addEventListener` у такого значения браузер может сообщить:

```text
Cannot read properties of null (reading 'addEventListener')
```

`null` — подсказка: программа ожидала элемент, но ничего не нашла. Сверь селектор с `id` в HTML. Также проверь подключение скрипта и атрибут `defer`.

> «Всё, пиздец, JavaScript сломан». Расследование: в `main-button` потерялась одна буква. Масштаб катастрофы сократился до опечатки. Исправь её и повтори проверку.

Для наблюдения можно ввести в консоли:

```javascript
document.querySelector("#main-button").textContent
```

Браузер покажет текущий текст кнопки. Сравни результат до и после нажатия. Это помогает проверить, что именно сейчас находится в документе.

### 7.4. Посмотри на страницу глазами браузера

Нажми **Ctrl+Shift+I** и открой вкладку **Elements / Элементы**. В ней видно дерево элементов текущей страницы. Найди кнопку и посмотри её текст до и после нажатия.

В панели **Styles / Стили** можно увидеть применённые CSS-правила и попробовать изменить значение прямо в браузере. Это удобно для эксперимента с цветом или отступом.

Изменение через инструменты разработчика меняет открытый документ. Чтобы результат сохранился после перезагрузки и попал на хостинг, перенеси нужные значения в исходный файл в редакторе, сохрани его и выполни обычный рабочий процесс.

### 7.5. Частые ситуации

| Что произошло | С чего начать проверку |
| --- | --- |
| Вместо страницы виден исходный код | Проверь расширение `index.html` и что файл открыт именно в браузере |
| CSS не применяется | Проверь имя `style.css`, расположение рядом с HTML, `href="./style.css"` и сохранение |
| Кнопка не реагирует | Проверь `script.js`, Console, `defer` и совпадение `main-button` в HTML и JavaScript |
| Цвет меняется только при наведении | Посмотри, какое правило редактировал: `button` или `button:hover` |
| Новая надпись исчезла после обновления | Для нашей программы это ожидаемо: заново загрузился исходный HTML |
| Локально работает, а на хостинге — нет | Проверь, отправлены ли все файлы, регистр букв в именах и относительные пути вместо `C:\...` |
| Сайт отвечает `404` | Проверь `/marvel-landing/` в адресе, наличие `index.html` в корне `main`, настройки Pages и результат публикации |
| После `push` ещё видна старая версия | Проверь вкладку Actions, дождись завершения, затем попробуй Ctrl+F5 |
| `git` не найден | Перезапусти VS Code после установки и проверь доступность Git в командной строке |
| `not a git repository` | Выполни `Get-Location`: терминал должен быть внутри папки проекта, где запускал `git init` |
| `Author identity unknown` | Проверь `user.name` и `user.email` из главы 4 |
| `nothing to commit` | Проверь сохранение и `git status`: возможно, изменения уже записаны или нужные файлы не подготовлены |
| `remote origin already exists` | Связь уже добавлена. Посмотри `git remote -v` и сравни адрес с репозиторием |
| `git push` сообщает об ошибке доступа | Проверь адрес репозитория, владельца и аккаунт, под которым завершил авторизацию |
| `git push` отклонён с `fetch first` или `non-fast-forward` | На GitHub есть другая история. Прочитай сообщение и разберись с ней перед объединением; при первом таком случае попроси помощь |

Фразы `nothing to commit` и `working tree clean` сами по себе не доказывают, что сайт опубликован. Они описывают состояние файлов и локального репозитория. Отправку проверяют по результату `push`, а публикацию — в Pages и Actions.

### 7.6. Как попросить помощь, чтобы её было легче получить

Опиши:

- что ты делал;
- какой результат ожидал;
- что получилось;
- точный текст ошибки;
- какую проверку уже выполнил.

Пример: «После переименования CSS кнопка стала серой. В HTML написано style.css, а в папке файл называется styles.css. Правильно ли я понимаю, что имена должны совпадать?»

> Если всё заебало: сохрани файлы, запиши, что именно не работает, и сделай паузу. Потом вернись к одному конкретному вопросу. Тильт не компилируется, зато список фактов отлично читается. Ошибка в коде описывает проблему в коде, а не твои способности.
